# First-delivery acceptance ledger

The software can perform a check without the available source data being sufficient to certify a student’s whole plan. `UNKNOWN` remains an explicit result.

| Journey | Software capability | Real-source coverage | Verified programme coverage |
| --- | --- | --- | --- |
| Course codes and degree groups | One code policy accepts 3- and 4-digit forms, including X-series codes. AI/ML major parses as nine six-unit courses. | Both 2026 and 2027 AI/ML source fragments include `STATX100`; official X-series codes are not placeholders. | The 54-unit AI/ML course list is structured; the degree as a whole remains partial where course versions or future offerings are unknown. |
| Source ingestion | Robots-aware, paced, cached, year-aware parser with immutable revisions and atomic active-snapshot replacement. | Discovery starts from Bachelor of Computer Science degree/major references and follows requisites. This is a bounded corpus, not all Adelaide courses. | Year-mismatched or missing pages are not certified. Degree year evidence is separately checked. |
| Requisites and levels | Typed three-valued rules; title-bearing `all of`/`one of` lists and antirequisite conditions; explicit course level. | Real `COMP2052` wording is parsed. Ambiguous `COMP3045` wording remains `UNKNOWN`. `INFO1002` demonstrates why code digits cannot establish level. | Unparsed wording and missing level remain unknown. Reviewed overrides require source-hash provenance. |
| Local planner | IndexedDB per catalogue year, strict JSON import/export, suggested sequence, attempts, named credits and waivers. | Suggested study periods come from the degree page, but are distinct from independently verified course offerings. | A suggested future period alone does not certify takeability. |
| Validation and planning | Selected programme rules stay pinned to its catalogue year; scheduled courses use their own calendar-year version for units, rules, levels and offerings. Fastest path and period-specific `can-take` are separate. | Only published offerings can support a verified generated plan. Unknown assessments are separate from courses with no listed exam. | The current snapshot cannot certify a complete three-year BComp plan. Missing future offerings are not extrapolated. |
| Course search | BGE small English vectors, pgvector evidence, lexical fallback, selected-pathway requirement fit, and separate takeability status. | UI shows the currently ingested corpus and vector-indexed count. No broad elective coverage is claimed. | `COUNTS_AS_ELECTIVE` is structural fit within the known rule; it does not assert that a student can take the course now. |
| Database and deployment | Multiple degrees can coexist in one year; explicit Alembic migrations work from an empty PostgreSQL schema. Active stale versions and evidence are removed while revision payloads remain. | Local PostgreSQL/pgvector integration tests use disposable schemas. | Multi-degree storage does not mean additional degrees have been verified for the first UI. |
| Browser and API | React/TypeScript screens, source-status badge separate from academic evaluation, rate limits, transient plan requests, and no student account database. | Browser tests cover Chromium, Firefox, WebKit, and mobile Safari emulation with committed fixtures. | Physical devices and current live-source availability require separate checks. |

The latest `slop quality` output is the source for numeric coverage. At the corrective snapshot: 2026 has 45 ingested course versions, 9 with listed offerings, and 30 unverified versions; 2027 has 75 versions, none with listed offerings, and 64 unverified versions. All 120 versions have evidence vectors in the local checked database, which measures indexing of this bounded corpus, not university-wide completeness.
