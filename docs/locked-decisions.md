### First-delivery acceptance criteria

The first delivery is accepted when all of these work without manually editing database state:

* **Catalogue ingestion:** ingest the 2026 and 2027 Bachelor of Computer Science catalogue plus all courses referenced by its verified rules; rerunning ingestion is idempotent and produces provenance/content hashes.
* **Degree browsing:** open the degree, switch catalogue year, inspect requirements, majors/specialisations, course descriptions and source links.
* **Planner:** create a local plan, select the degree/year, drag or otherwise move courses between study periods, mark courses completed, and add local provisional credit/waiver entries.
* **Strict validation:** show satisfied, unsatisfied and `UNKNOWN` requirements separately. No AI-generated interpretation may turn `UNKNOWN` into valid.
* **Prerequisite reasoning:** selecting a blocked course explains exactly which prerequisite expression failed.
* **Fastest path:** for a blocked target course, calculate the earliest valid prerequisite sequence using actual available teaching periods known to the catalogue.
* **Plan generation:** generate a valid remaining plan and support preferences such as `avoid exams early`, `prefer no-exam courses`, or `balanced exam/non-exam load`. Preferences are optimisation objectives; prerequisite and program requirements are hard constraints.
* **Semantic elective search:** a query such as `CAD`, `3D modelling`, or a plain-English interest returns relevant courses and shows the matching course overview/outcome/assessment evidence. Degree-compatible courses rank ahead of unrelated courses, with an option to see all matches.
* **Natural-language router:** the single search input can route at minimum to degree search, course/semantic search, prerequisite questions and planner questions. Generative AI is not required for routing.
* **Automated verification:** parser fixture tests, rule-AST tests, prerequisite graph tests, constraint/planner tests, API integration tests and Playwright tests for the core flows above all run in CI. Every hand-verified Bachelor of Computer Science requirement must have an expected structured-rule fixture rather than relying only on percentage-based coverage.
* **Parser safety:** unfamiliar/unparsed academic wording must emit a parser warning and an unresolved rule. It must never silently disappear.
* **Deployment:** `docker compose up` starts a complete development system; migrations work from an empty database; there are health/readiness endpoints, environment examples, an ingestion command, a fixture-loading command and production deployment configuration.
* **Data recovery:** browser plans can be exported/imported as a versioned JSON file so clearing browser storage is not the only copy of a student's plan.
* **No account dependency:** no sign-in, student database record, review system or community feature is required.

For career exploration, I would use **JSA + O*NET datasets as knowledge sources**, but not scrape Seek, Indeed, LinkedIn or other job-listing sites. JSA currently permits broad reuse of most site content under CC BY 4.0 with exceptions, while O*NET's downloadable database has explicit CC BY 4.0 terms. ([Jobs and Skills Australia][3])
